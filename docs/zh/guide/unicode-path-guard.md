# Unicode 路径防护（CVE-2025-48567）

管理器的「内核策略」页提供默认关闭的 **Unicode 路径防护** 开关。它通过 SUMH 的内核路径钩子阻断特定 Unicode 目录别名，属于针对 CVE-2025-48567 的补偿防护，不表示设备中的 MediaProvider 已安装官方修复。

## 漏洞原理与官方修复

[NVD 记录](https://nvd.nist.gov/vuln/detail/CVE-2025-48567)将问题描述为 Unicode 规范化不一致导致的文件路径过滤绕过，可能造成需要用户交互的本地权限提升。Android 官方公告列出的受影响版本是 Android 14、15、16。CVE 编号中的 2025 是编号年份；公开修复位于 [2026 年 3 月 Android 安全公告](https://source.android.com/docs/security/bulletin/2026/2026-03-01)的 **2026-03-01** 补丁级别，同时属于 MediaProvider 的 Google Play 系统更新范围。

[AOSP 修复 237fb89f532504aeef0c3ee2038aad89a8a66180](https://android.googlesource.com/platform/packages/providers/MediaProvider/+/237fb89f532504aeef0c3ee2038aad89a8a66180)解释了不一致的来源：MediaProvider 的路径正则检查看到了默认可忽略字符，而底层文件系统的 Unicode 文件名比较忽略了这些字符。于是两个层面对同一输入作出不同判断，应用私有目录的访问检查可能被绕过。这涉及文件名语义，不是文本排版卡死。

官方修改先做 NFD 规范化，再按 ICU 的 `DEFAULT_IGNORABLE_CODE_POINT` 属性移除字符，然后执行权限检查。仅删除 U+200B，或把所有非 ASCII 字符都当作危险字符，都不等价于该修复。该提交的开关是固定只读的 `enable_path_sanitization`，不能假设在未修复固件中写入一个系统属性就能开启补丁。

## 本仓库的处理方式

SUMH 普通路径隐藏规则按具体名称匹配，无法枚举任意位置、任意次数插入的不可见字符。因此此功能使用独立的 SUMH 路径钩子，检查单个目录组件：只有包含默认可忽略字符，且去除后按 ASCII 大小写比较等于 `Android`、`data` 或 `obb` 时才拒绝访问。原始路径不会被悄悄重写。

防护覆盖标准 casefold 文件系统的 `generic_ci_d_hash`，以及 FUSE 的查找、原子打开和缓存重新验证入口。它在路径遍历层检查组件，因此不靠 `/sdcard` 等路径前缀来识别，相对路径、目录文件描述符和符号链接中的后续组件也走相同检查。FUSE 检查会保守地拒绝这种组件名，即使该 FUSE 文件系统本身不使用 casefold。

防护独立于 SUMH 模块的 VIEW/SPOOF 策略，不因应用隐藏或卸载模块而关闭。启用时必须确认所需钩子可用；注册失败会撤销本次注册并报告失败，不把只安装了部分钩子的状态显示成已启用。

能力范围限定为 ARM64 Linux 6.1、6.6、6.12、6.18 系列，且要求 Unicode、kprobes 和内建 FUSE。仅有对应版本号还不够，运行时也必须找到并成功注册所需入口。模块形式的 FUSE 不报告支持，避免模块卸载后探针失效而界面仍显示已启用；关闭后重新开启会重新初始化探针描述符。

这是有意收窄的别名阻断，不实现 MediaProvider 的全部身份与权限语义，也不替换、修改或绕过签名安装 MediaProvider/APEX。厂商改写的文件系统入口仍需设备验证。刻意包含不可见字符、去除后恰好与上述名称相同的普通目录也会被拒绝；中文文件名、普通 emoji 和不形成这些名称的连接符用法不在阻断范围内。

## 使用与撤销

1. 更新 Manager、ksud 和内核模块；只更新 APK 不会给旧内核增加能力。
2. 在「内核策略」中开启 Unicode 路径防护，确认运行状态显示已启用。配置通过既有 feature 配置保存并在启动时恢复。
3. 已经打开的文件或目录句柄不会因开关被撤回。建议启用后重启，清除先前保留的句柄和挂载状态；开关不会自动杀死应用或重启设备。
4. 关闭开关可撤销阻断并保存关闭状态，不修改已有文件，也不清空其他 SUMH 规则。

CLI 接口：

```sh
/data/adb/ksud feature set-save unicode_path_guard 1
/data/adb/ksud feature get unicode_path_guard
/data/adb/ksud feature get unicode_path_guard_status
/data/adb/ksud feature set-save unicode_path_guard 0
```

功能 ID 109 为可保存开关。ID 110 为只读运行状态：0 关闭，1 已启用，2 不支持。状态值不是布尔值；2 不能解释成“已开启”。安装了官方更新的设备也可保留关闭状态；本功能不通过可伪装的安全补丁日期自动声称设备已修复。

## 性能与验证边界

实现只检查路径组件，不扫描文件内容、不拦截每次 `read`/`write`，不分配每次访问的临时路径缓冲区。按 VFS 提供的实际组件长度检查，普通名称可以提前结束匹配；不能假设输入已通过 255 字节文件名限制，因为缓存查找可能先于底层长度检查。关闭时不保留专用访问探针，共用的 FUSE 检查只读取关闭标志。这是源码层面的开销分析，不是真机性能数据。

主机回归入口：

```sh
python3 scripts/ci/test_sumh_unicode_guard.py --cc clang
```

测试覆盖默认可忽略字符集合的每个码点和插入位置、UTF-8 边界、大小写、正常名称、超过 255 字节的别名、钩子失败回滚、重复开关以及不支持的配置。它使用内核 API 替身，不能证明真实内核上的探针行为。Manager 另有运行状态边界测试，确保状态 2 不会被当作“已开启”。完整发布验证还需四个受支持 KMI 的内核构建、ksud 构建和 Manager 编译/单元测试。

真机验证应在隔离测试设备和合成文件夹上进行：分别验证 FUSE 冷/热缓存、底层 casefold、相对路径、目录句柄、符号链接、关闭/开启/重启恢复、应用模块隐藏、常见合法 Unicode 名称；不要以读取其他应用数据来验证。比较防护关闭/开启时相同目录遍历与小文件打开任务的耗时、CPU 和延迟分位数。没有这些数据时，不宣称 SUMH 性能优于其他实现。若存在明显回退，优先使用官方 MediaProvider 更新或在自编译系统中回移上游修复，而不是扩大为全量文本或文件内容过滤。
